# JSON Emit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The pipeline emits `frontend/src/lib/data/dataset.json`, shaped field-for-field like the frontend's `MockDataset` TypeScript interface, and the frontend is pointed at it instead of the seeded mock — completing frontend.md's "swap the mock module for real emitted JSON" step now that the mock (built in the prior plan) has pinned the exact shape.

**Architecture:** `pipeline/src/mlbb_pipeline/emit.py` adds `dataset_from_db(conn) -> dict` (SQLite rows → the same camelCase dict shape `frontend/src/lib/types.ts` already declares) and `write_dataset(dataset, path)`. `build.py`'s `main()` calls both after a successful `check_no_regression`, so one `mlbb-build` run produces both the committed `data/mlbb.db` and the committed `frontend/src/lib/data/dataset.json` from the same in-memory data — never two passes that could drift. On the frontend side, `src/lib/mock/` is deleted entirely (frontend.md, explicit: "Swapping to real data is deleting `src/lib/mock/`... The screens never know") except `metrics.ts`, which moves to `src/lib/metrics.ts` unchanged — it was never mock-specific, only `generator.ts`/`rng.ts`/`mock/data.ts` were. A new `src/lib/data.ts` imports the committed JSON directly (Vite handles `.json` imports natively). The three route files' two import lines each are the only other files touched.

**Tech Stack:** Python 3.12 (stdlib `json`), TypeScript/Vite (native JSON import), pytest, Vitest.

**Spec:** `docs/frontend.md` ("Swap the mock module for real emitted JSON... The screens never know"), `docs/stack.md` (build strategy step 5: "Compute metrics, emit JSON to the frontend"), `docs/database.md` (source schema), `frontend/src/lib/types.ts` (target shape, already committed by the frontend-mockup plan)

## Global Constraints

- **Field names are fixed by `frontend/src/lib/types.ts`**, not invented here: `canonicalName`, `shortCode`, `seriesId`, `team1Id`, `team2Id`, `team1Side`, `winnerId`, `gameLength`, `gameNumberInSeries`, `playedAt`, `matchId`, `teamId`, `heroId`, `isBan`. `emit.py` maps SQLite's snake_case columns to these exactly; a mismatch would silently render `undefined` in every screen, which is precisely what roadmap.md's still-open "generated TypeScript types from Pydantic" step exists to prevent long-term — out of scope for this plan, noted below.
- **One JSON file, not four.** `frontend/src/lib/mock/data.ts` exports a single `MockDataset` object; the real replacement (`src/lib/data.ts`) must be a drop-in, so `emit.py` writes one `dataset.json` containing `{teams, heroes, matches, drafts}`, not separate files per table.
- **`is_ban` is stored as SQLite `INTEGER` (0/1)** (schema.py) and must be emitted as a real JSON boolean (`bool(row["is_ban"])`), matching `DraftRow.isBan: boolean`.
- **No new frontend behavior.** `metrics.ts`'s formulas are untouched by this plan — only its file path changes (`mock/metrics.ts` → `metrics.ts`) and its import path in the three routes. If any screen's numbers look different after the swap, that is real data replacing synthetic mock data, not a bug to chase inside this plan.
- Python 3.12, `uv`; frontend uses whatever Node/npm this repo already has installed (verified working in the frontend-mockup plan).

```python
# pipeline/src/mlbb_pipeline/emit.py
from __future__ import annotations

import sqlite3


def dataset_from_db(conn: sqlite3.Connection) -> dict:
    """Every row of teams/heroes/matches/drafts, field names mapped to
    the camelCase shape frontend/src/lib/types.ts declares (MockDataset,
    Team, Hero, MatchRow, DraftRow) — the frontend's data.ts imports
    this dict verbatim as JSON, so the shape must match exactly."""
    teams = [
        {"id": r[0], "canonicalName": r[1], "shortCode": r[2]}
        for r in conn.execute("SELECT id, canonical_name, short_code FROM teams")
    ]
    heroes = [
        {"id": r[0], "canonicalName": r[1]}
        for r in conn.execute("SELECT id, canonical_name FROM heroes")
    ]
    matches = [
        {
            "id": r[0],
            "seriesId": r[1],
            "season": r[2],
            "stage": r[3],
            "team1Id": r[4],
            "team2Id": r[5],
            "team1Side": r[6],
            "winnerId": r[7],
            "gameLength": r[8],
            "gameNumberInSeries": r[9],
            "playedAt": r[10],
        }
        for r in conn.execute(
            "SELECT id, series_id, season, stage, team1_id, team2_id, "
            "team1_side, winner_id, game_length, game_number_in_series, played_at "
            "FROM matches"
        )
    ]
    drafts = [
        {
            "id": r[0],
            "matchId": r[1],
            "teamId": r[2],
            "slot": r[3],
            "heroId": r[4],
            "isBan": bool(r[5]),
        }
        for r in conn.execute(
            "SELECT id, match_id, team_id, slot, hero_id, is_ban FROM drafts"
        )
    ]
    return {"teams": teams, "heroes": heroes, "matches": matches, "drafts": drafts}
```

```python
import json
from pathlib import Path


def write_dataset(dataset: dict, path: Path) -> None:
    """Write dataset as JSON to path, creating parent directories as
    needed. Vite/SvelteKit import JSON files natively, so the frontend
    side needs nothing beyond a plain `import dataset from '...json'`."""
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(json.dumps(dataset, indent=2), encoding="utf-8")
```

## Not in this plan — the live run

- **Actually running `mlbb-build` against the real `data/mlbb.db`** to produce `frontend/src/lib/data/dataset.json` for real and committing it. A one-shot operational step, same pattern as the backfill and SQLite-build plans' live runs. Runbook: `uv run --project pipeline mlbb-build`, then `cd frontend && npm run build && npm run test`, then a browser check that Team Scouting/League Overview/Match Log show real S17+S18 numbers (e.g., freya's presence lead over guinevere, verified in the metrics plan, should now be visible on `/league`).
- **A real `generatedAt` timestamp.** `data.ts`'s placeholder (`new Date().toISOString()`, evaluated at every page load) is wrong for a build-time-only static site — every visitor would see "just now" regardless of when the data was actually built. Fixing this needs the pipeline to emit a real timestamp into the JSON (or a sibling file) and is a small, separate follow-up.
- **Generated TypeScript types from the Pydantic models** (roadmap.md). This plan hand-maintains the field mapping in `emit.py` and trusts `test_emit.py`'s exact-keys assertions to catch drift; automatic generation is the more permanent fix, tracked separately.
- **GitHub Actions weekly cron** (stack.md). Automating the `mlbb-build` run is a separate, later concern.
