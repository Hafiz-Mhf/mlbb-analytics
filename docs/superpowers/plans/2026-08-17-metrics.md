# Metrics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pure Python functions over the SQLite archive (`data/mlbb.db`) that compute the two core metrics — presence and HHI, overall and per-role, for any team or the league baseline — matching CLAUDE.md's exact formulas. No JSON emission and no frontend work in this plan; those come after, once the frontend mock work (frontend.md, "Mock-first build order") has had a chance to pin down the exact JSON shape each screen needs.

**Architecture:** `metrics.py` has two layers. Three private scope helpers (`_instance_count`, `_draft_counts`, `_pick_counts`) do the SQL against `matches`/`drafts`/`heroes` and know nothing about presence or HHI as concepts. Four public functions (`presence`, `pick_rate_by_role`, `hhi`, `hhi_by_role`) apply CLAUDE.md's formulas to what the helpers return. Every function takes the same three optional filters — `team_id`, `season`, and (for the by-role variants) `role` — so "team vs. league baseline" is never a separate code path, just the same function called once with a `team_id` and once without (planning.md: "every number in this tool appears next to its league baseline").

**Tech Stack:** Python 3.12, `uv`, stdlib `sqlite3`, pytest. No new dependency.

**Spec:** `CLAUDE.md` (exact formulas: "presence (picks+bans / games)... HHI (sum of squared pick shares)"), `docs/planning.md` ("Must have": presence and HHI, overall and per-role; baseline-adjusted comparison on every stat), `docs/database.md` (schema this reads), `docs/data-source.md` (role-ordering, hero alias facts used to sanity-check results against real data)

## Global Constraints

- **Presence formula, exact:** `(times a team picked-or-banned a hero) / (games that team played)`, per CLAUDE.md. Numerator counts every matching `drafts` row (picks and bans together, no `is_ban` filter) — a hero picked and separately banned by the same team in the same game (were it ever to happen) counts twice, because CLAUDE.md's wording is literal, not deduplicated.
- **HHI formula, exact:** `sum of squared pick shares` — **picks only**, never bans, per CLAUDE.md. A pick share is `(a hero's pick count in scope) / (total picks in scope)`; shares sum to 1 across heroes.
- **League baseline is not a separate concept.** Every function accepts `team_id: int | None`; `None` means "every team, pooled" — the exact same query, just without the `team_id` filter. This is what makes a baseline comparison "call the same function twice," per planning.md's core mechanic.
- **"Per role" applies to picks only**, never bans — `drafts.slot` means role for picks but ban-order for bans (database.md), so a role filter on bans would be meaningless. `pick_rate_by_role`/`hhi_by_role` therefore always imply `is_ban = 0` internally; there is no role-filtered presence-of-bans.
- **Season scope.** `season: str | None` — `None` means all seasons pooled (matches `matches.season` being unfiltered). Values are the exact strings stored in `matches.season` ("17", "18"), matching `MatchRecord.season` (models.py) and the schema (schema.py).
- **League-scope denominators double-count on purpose.** A played game has two team-instances (team1's picks/bans, team2's picks/bans). `team_id=None` (league scope) must therefore divide by `2 × game_count`, not `game_count` — see `_instance_count` in Task 1.
- Python 3.12, `uv` for venv/deps/lockfile (stack.md). Reads `data/mlbb.db` (built by `build.py`, merged) — never writes to it.

```python
# pipeline/src/mlbb_pipeline/metrics.py
from __future__ import annotations

import sqlite3


def _instance_count(
    conn: sqlite3.Connection,
    *,
    team_id: int | None = None,
    season: str | None = None,
) -> int:
    """Denominator for presence and pick_rate_by_role. A played game has
    two team-instances (each side's own picks/bans); league scope
    (team_id=None) counts both, so it is 2x the game count, not 1x."""
    if team_id is not None:
        row = conn.execute(
            "SELECT COUNT(*) FROM matches "
            "WHERE (team1_id = ? OR team2_id = ?) "
            "AND (? IS NULL OR season = ?)",
            (team_id, team_id, season, season),
        ).fetchone()
        return row[0]

    row = conn.execute(
        "SELECT COUNT(*) FROM matches WHERE (? IS NULL OR season = ?)",
        (season, season),
    ).fetchone()
    return row[0] * 2


def _draft_counts(
    conn: sqlite3.Connection,
    *,
    team_id: int | None = None,
    season: str | None = None,
) -> dict[str, int]:
    """Picks and bans combined, per hero — presence's numerator."""
    rows = conn.execute(
        """SELECT h.canonical_name, COUNT(*)
           FROM drafts d
           JOIN heroes h ON h.id = d.hero_id
           JOIN matches m ON m.id = d.match_id
           WHERE (? IS NULL OR d.team_id = ?)
           AND (? IS NULL OR m.season = ?)
           GROUP BY h.canonical_name""",
        (team_id, team_id, season, season),
    ).fetchall()
    return dict(rows)


def _pick_counts(
    conn: sqlite3.Connection,
    *,
    team_id: int | None = None,
    season: str | None = None,
    role: int | None = None,
) -> dict[str, int]:
    """Picks only (is_ban = 0), per hero — HHI's and pick_rate_by_role's
    numerator. role, if given, filters to that slot (role for picks only,
    per database.md — never call this with a role for ban rows)."""
    rows = conn.execute(
        """SELECT h.canonical_name, COUNT(*)
           FROM drafts d
           JOIN heroes h ON h.id = d.hero_id
           JOIN matches m ON m.id = d.match_id
           WHERE d.is_ban = 0
           AND (? IS NULL OR d.team_id = ?)
           AND (? IS NULL OR m.season = ?)
           AND (? IS NULL OR d.slot = ?)
           GROUP BY h.canonical_name""",
        (team_id, team_id, season, season, role, role),
    ).fetchall()
    return dict(rows)
```

```python
def presence(
    conn: sqlite3.Connection,
    *,
    team_id: int | None = None,
    season: str | None = None,
) -> dict[str, float]:
    """(picks+bans) / games — CLAUDE.md's exact formula. team_id=None is
    the league baseline: every team's own picks/bans in their own games,
    pooled (planning.md's "every number next to its league baseline")."""
    denominator = _instance_count(conn, team_id=team_id, season=season)
    if denominator == 0:
        return {}
    counts = _draft_counts(conn, team_id=team_id, season=season)
    return {hero: count / denominator for hero, count in counts.items()}


def pick_rate_by_role(
    conn: sqlite3.Connection,
    *,
    role: int,
    team_id: int | None = None,
    season: str | None = None,
) -> dict[str, float]:
    """How often a hero is picked specifically in `role` (1=EXP..5=Roam),
    per game in scope. The per-role cut of presence — picks only, since
    a ban's slot is ban-order, not role (database.md)."""
    denominator = _instance_count(conn, team_id=team_id, season=season)
    if denominator == 0:
        return {}
    counts = _pick_counts(conn, team_id=team_id, season=season, role=role)
    return {hero: count / denominator for hero, count in counts.items()}


def hhi(
    conn: sqlite3.Connection,
    *,
    team_id: int | None = None,
    season: str | None = None,
) -> float:
    """Sum of squared pick shares — CLAUDE.md's exact formula. Picks
    only, never bans. 0.0 when there are no picks in scope."""
    counts = _pick_counts(conn, team_id=team_id, season=season)
    total = sum(counts.values())
    if total == 0:
        return 0.0
    return sum((count / total) ** 2 for count in counts.values())


def hhi_by_role(
    conn: sqlite3.Connection,
    *,
    role: int,
    team_id: int | None = None,
    season: str | None = None,
) -> float:
    """Same formula as hhi(), restricted to picks in one role slot —
    concentration within just that role's hero pool."""
    counts = _pick_counts(conn, team_id=team_id, season=season, role=role)
    total = sum(counts.values())
    if total == 0:
        return 0.0
    return sum((count / total) ** 2 for count in counts.values())
```

## Not in this plan

- **JSON emission.** A separate plan, after frontend mock work (frontend.md, "Mock-first build order") has pinned down what shape each of the three routes (Team Scouting, League Overview, Match Log) actually needs. Emitting a guessed shape now risks reshaping it twice.
- **Flex rate.** planning.md lists it under "Should have," not "Must have," and its exact formula (hero's distribution across role slots vs. how often a team uses a hero off its league-wide modal role) has more open judgment calls than presence/HHI. A follow-up once the "Must have" metrics are proven against real data.
- **CLI / script wiring.** `presence`/`hhi` are library functions called from wherever JSON emission ends up living; no standalone `mlbb-metrics` command is needed for that.
